Method and limitations

  • Legacy side. Expected outputs are computed by a reimplementation of each query that follows the source engine's documented semantics (integer division, case insensitive collation, LEN, CAST truncation, CONNECT BY order). Real SQL Server or Oracle output can replace them via harness/capture_legacy.py.
  • Snowflake side. Converted SQL runs on fakesnow (local Snowflake emulator on DuckDB).
  • Accuracy. A query counts as accurate only when columns, row count, every value (numeric tolerance 1e-6) and row order all match.
  • Emulator shims (no op on real Snowflake, applied to both converters): Q02: TO_CHAR(o.order_date, ...) input cast to DATE; Q06: TO_CHAR(o.order_date, ...) input cast to DATE.
  • Not verifiable locally means valid Snowflake syntax the emulator cannot execute faithfully; it is excluded from the accuracy denominator.
  • Documentation. 8 of 8 generated documents contain every required section.
